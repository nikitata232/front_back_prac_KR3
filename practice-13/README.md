# Практика 13 — Service Worker

## Что это

Веб-приложение для управления заметками с поддержкой офлайн-режима через технологию **Service Worker**.

## Структура проекта

```
practice-13/
├── index.html   — разметка приложения
├── app.js       — логика заметок и регистрация Service Worker
├── sw.js        — скрипт Service Worker
└── README.md
```

## Что сделано

### Service Worker (`sw.js`)

- **`install`** — при первой установке SW открывает кэш `notes-cache-v1` и сохраняет в него все статические файлы (`/`, `index.html`, `app.js`). `skipWaiting()` позволяет новому SW сразу взять управление без ожидания закрытия старых вкладок.
- **`activate`** — очищает устаревшие кэши (с другими именами). `clients.claim()` позволяет SW немедленно взять под контроль открытые вкладки.
- **`fetch`** — перехватывает все сетевые запросы. Стратегия **Cache First**: сначала ищет ответ в кэше, при отсутствии — идёт в сеть.

### Приложение (`app.js`)

- Заметки хранятся в `localStorage` — данные не теряются при перезагрузке и доступны офлайн.
- Баннер «Вы офлайн» отображается при потере соединения через события `online` / `offline`.
- Service Worker регистрируется в событии `load` через `navigator.serviceWorker.register('/sw.js')`.

## Как запустить

Service Worker работает только через HTTP(S)-сервер (не через `file://`).

```bash
# Вариант 1: npx
npx live-server

# Вариант 2: http-server
npx http-server -p 8080
```

Открыть в браузере: `http://localhost:8080`

## Как проверить офлайн-режим

1. Открыть DevTools → вкладка **Application** → **Service Workers** — убедиться что SW активен.
2. Перейти на **Cache Storage** → `notes-cache-v1` — увидеть закэшированные файлы.
3. Во вкладке **Network** поставить галочку **Offline**.
4. Обновить страницу — она загрузится из кэша.
5. Добавление заметок продолжает работать офлайн (данные в `localStorage`).
